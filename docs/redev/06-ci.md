# CI 与已知 flake

`main` 必须保持可构建、可测试。本文件记录 CI 的门槛、以及**上游遗留用例的已知 flake**
（为什么被跳过、怎么复现、怎么才算修好）。

## 门槛（`.github/workflows/ci.yml`）

| 步骤 | 是否阻塞 | 说明 |
|---|---|---|
| `go build ./...` | ✅ | 全仓库编译 |
| `go vet ./...` | ✅ | 静态检查 |
| `gofmt`（新增代码） | ✅ | 只检查本仓库新增的规范执行层；上游代码保持原样 |
| `go test ./... -p 1` | ✅ | 全部单元/集成测试（CI 内起临时 PostgreSQL）；失败的包自动重跑一次 |
| 上游已知 flake | ⬜ | `continue-on-error`，只观察不阻塞 |

## 为什么 `-p 1`

所有测试包共用**同一个** PostgreSQL 实例。并行跑包会互相踩数据，已实际观察到
`ERROR: deadlock detected (SQLSTATE 40P01)` 与"任务作用域缺失"这类跨包干扰。
串行是单库 CI 的正确做法；如果你想并行，需要按包分配独立数据库。

## 已知 flake（已从硬门槛中 `-skip`）

> 判定标准：**在干净数据库（CI 首次运行）上失败，在开发者本机（库里有历史数据）上通过**。
> 这不是"偶发"，而是**用例隐式依赖库内状态**。修好一条就从 `-skip` 列表移除。

### 1. `agent/TestGraphOverviewExpandsAssociatedCompanyScope`

- 现象：`blackboard_inheritance_test.go:87: task scope missing: <nil>`
- 根因：`graphOverviewData()` 的 `coverage.scope` 依赖任务作用域数据，而干净库里
  公司作用域→任务作用域的展开结果为空。
- 修复方向：用例显式构造 `task_scope`（或先跑展开逻辑），不要在断言里依赖隐式落库。

### 2. `agent/TestBlackboardToolsReadDirectSources`

- 现象：`ERROR: deadlock detected (SQLSTATE 40P01)`
- 根因：用例内部并发写 activity/blackboard，事务获取顺序不稳定。
- 修复方向：统一加锁顺序，或让测试串行化相关写入。

### 3. `TempDir 清理竞态`（同一类，不止一条用例）

- 已知实例：`server/TestConversationPatchReturnsPinState`、
  `server/TestInheritedActivityDetailAndRelationDeletion`
- 现象：`TempDir RemoveAll cleanup: directory not empty`，伴随 `sql: database is closed`
- 根因：用例结束时后台协程（activity/checkpoint 写入）仍在写工作目录。哪条用例先撞上
  取决于调度，所以修一条还会换一条冒出来。
- 缓解：CI 对**失败的包**自动重跑一次；真故障会第二次继续失败。根治方向是让 Manager
  提供 Drain/Close 语义，用例结束前等待后台写入退出。

## 已修复

- `llmrec/TestSideUsageRecordedOnceOnConsumerCancellation`：`llm_usage` 由 manager 启动时
  按需建表、不在 `schema.sql` 里，干净库上 `relation does not exist`。已改为用例自行
  `EnsureLLMUsageTable()`（commit `fix(test,ci): llmrec 自建 llm_usage 表…`）。

### 4. `db/TestCompanyScopeAttribution`（只在复用同一个库时）

- 现象：`in-CIDR ip (insert-time) company_id = N, want M`
- 根因：用例假设库里没有别的公司级 scope 记录；同一套 PG 反复跑 server 用例会留下数据，
  全局 company attribution 取到上一次的 company。
- 缓解：本地先在干净库上跑（`DROP DATABASE` + `CREATE DATABASE`），或让 db 包自带临时库；
  CI 每次都是全新服务，不会撞上。同理，`db` 与 `server` 两包**不要**对着同一个复用库并行跑，
  会互相看到对方留下的状态（表现为 `sql: database is closed` / 认证与挂起用例失败）。

## 本地跑全套

```bash
# 需要一个可用的 PostgreSQL；db.Open 会自动建库
export ARTEX_PG_DSN='postgres://artex:artex@127.0.0.1:5432/artex?sslmode=disable'
go test ./... -count=1 -p 1
```
