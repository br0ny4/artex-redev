# 与上游 ARTEX v0.3.15 的差异总览

> 对照基线：上游 ARTEX v0.3.15（2026-10-07，作者闭源前最后一个公开版本，原仓库已 404）。
> 当前版本：`Fork-0.3.0` + 未发布切片（malware-triage、L3 端到端、0day 准入门）。
>
> 说明：本仓库首个提交 `f4b5c64` 是"可发布快照"，其中已经包含改名、许可声明、README
> 重写和策略引擎 v1 等发布前改造；此后的 24 个提交是增量。所以本文分两段讲：
> **A. 与上游的差异（含快照前的改造）**、**B. 发布之后的增量**。

## 0. 一句话定位

上游是"自动化渗透测试 Agent 平台"（跑起来就能扫，合规靠使用者的自律和提示词）；
本仓库把它做成**带工程化合规执行层的安全作业台**：判定在出口层强制执行、证据链可审计、
可全量停止，并把能力域从 Web 渗透扩到离线逆向 / 源码审计 / 样本分诊 / 0day 挖掘。

| | 上游 v0.3.15 | 现在（Fork-0.3.0+） |
|---|---|---|
| 定位 | 自动化渗透测试 Agent | 红队/蓝队/赏金/病毒分析通用的安全作业台 |
| 合规 | 靠提示词与使用者自律（RoE 层已被上游移除） | L1/L2/L3 三层工程强制 + 判定审计链 + Stop-All |
| 默认安全 | 全网卡监听、初始化接口可抢占、无登录限速 | 回环监听、初始化口令、登录限速、强制录制、出网收口 |
| 能力域 | Web 渗透 | Web 渗透 + 离线逆向 + 源码审计 + 样本分诊 + 0day 准入 |
| 结论可信度 | 无准入门 | 每条结论一份可复现 PoC + ≥5 条反例 + ≥3 次跨源撞车比对，导出强制 |

## 1. 安全默认值（直接影响"装完会不会裸奔"）

| 项 | 上游 | 现在 | 为什么改 |
|---|---|---|---|
| HTTP 监听 | `:8787`（所有网卡） | `127.0.0.1:8787` | 上游默认让一台没设密码的新实例直接暴露公网；Censys 扫到 1,465 台暴露控制台就是这类默认值的后果 |
| compose 端口 | `8787:8787` | `127.0.0.1:8787:8787` | 同上，只绑回环 |
| 初始化 | `POST /api/auth/init` 无认证可抢占 | 需要 `setup_token`（`ARTEX_SETUP_TOKEN` 或启动时打印的 32 位 hex） | 未初始化实例被人先占 = 直接接管 |
| 登录 | 无限速 | 同 IP 10 分钟 5 次失败锁 15 分钟（429 + Retry-After；`ARTEX_TRUST_PROXY=1` 才信 XFF） | 弱口令爆破 |
| 规范执行层未配置时 | — | 行为与上游一致（不装引擎=不拦） | 不替使用者做决定，但一旦配置即 fail-closed |
| 规范执行层已配置时 | — | 失败即拒绝：录制代理不可用→**拒绝启动**；流量录制**不可关闭** | L3 判定依赖录制代理，关掉即绕过；D7 决策"安装即 hard" |
| 离线域包运行时 | 无域包概念，一律当在线域 | 声明 `runtime.requires_traffic_capture: false` 的包（binary-re/source-audit/malware-triage）**免代理启动、录制可关**；在线域仍 fail-closed | 强制录制对离线分析是合规反噬：本地产物没有目标侧流量，不该先被迫配 MITM 证书 |

## 2. 合规执行层：从"提示词"到"工程强制"

上游的设计假设是"提示词会约束模型"，但它已经移除了 RoE 层，实际是"无规则命中即放行"。
本仓库新增独立 `policy/` 包（纯 Go、可单测、无 LLM 参与判定），三层接线：

| 层 | 位置 | 行为 |
|---|---|---|
| L1 命令/工具 | `guard` PreToolUse 前置 `applyPolicy` | 破坏性命令、内联解释器、`base64 -d \| sh`、敏感文件读取、靶标范围判定 |
| L3 请求出口 | `traffic/policy.go` | 命中即**不发包**，回 403 + `X-ArtEx-Policy`（说明"平台管控·非目标防御，未发送到目标"）；响应命中源码/密钥/超限则替换正文，原文不进模型上下文 |
| L2 出网收口 | `deploy/egress-lockdown/` | `internal: true` 网络 + 唯一 egress 代理（squid），`ARTEX_GLOBAL_PROXY`/`ARTEX_LLM_PROXY` 兜底 |
| 审计 | `db/policy_decisions` + `server/policy_api.go` | 每条判定哈希链（prev_hash/hash）、`GET /api/policy/chain` 可校验，判定写入不阻塞判定路径 |
| 停止 | `policy/hold.go` + `server/policy_hold_*.go` | 范围不明/语义判不清/预算耗尽/窗口过期 → **全量停止**（Stop-All），任务暂停省 token，操作员答复后才恢复 |

判定覆盖：授权清单（域名/网段/应用/API/本地目录）、内网段与云元数据默认 deny、CNAME
第三方托管按范围外、语义 A–F 分级（删除/覆盖/改名/送检/新建/读）、方法伪装、批量形态、
预算熔断、PII 与敏感内容识别。**判不清一律 hold**，不允许 LLM 放行（决策 D4）。

## 3. 域包（domain pack）抽象：从"一套策略"到"可切换的能力域"

上游只有一种"在线 Web 渗透"形态。现在策略按域打包，部署上下文用 `engagement.pack` 选择，
**未知包名直接报错**（不静默回退，否则"以为在跑 A 域、实际跑 B 域"）：

| 域包 | 用途 | 关键硬约束 |
|---|---|---|
| `web-pentest` | 在线渗透（继承上游能力） | 测试账号准入、接口语义分级、范围清单制 |
| `binary-re` | 样本/固件深度逆向、漏洞定位 | 情报回源白名单、禁宿主模拟器、送检需授权（R12/R13） |
| `source-audit` | 源码审计、0day 挖掘 | 授权范围=目录清单（`local_paths`）、默认零出网、被审计源码只读（R14/R15） |
| `malware-triage` | 应急第一小时批量分诊 | **一律不执行样本**（R13 `execute_sample_at_all`）、分诊工具白名单、更紧预算 |

每个域包 = `policy.yaml`（红线/预算/工具白名单）+ `verb-lexicon.yaml`（域内动作词表）
+ `deployment-context.example.yaml`（填写模板）。新增域包按
[07-domain-packs.md](07-domain-packs.md) 的"五步"即可。

## 4. 0day 准入：结论可信度的两道门

这是与上游最本质的差别之一：上游 finding 只要模型说"发现了"就能导出报告；现在**导出前强制**：

- **门三 · 触发验证**：**无 PoC 不算 finding**——一份可复制粘贴的触发输入 + 实际观察结果 +
  ≥2 次连续复现；一条 finding 只保留最新一份 PoC。
- **门一 · 反例验证**：≥5 条反例（阴性对照），每条写清要排除的误报路径、验证手法、
  预期/实际观察、可核对凭据（可引用真实 traffic id，服务端核对存在性）；`method|claim`
  归一化去重，**5 条副本不算 5 条反例**；任一条未通过即阻断。
- **门二 · 撞车比对**：≥3 次不同检索、覆盖 ≥2 类信息源（CVE/厂商公告/代码托管/漏洞库/搜索），
  命中已公开的同一致命漏洞即阻断并带出编号。
- 未过门导出返回 409 + 逐条原因；`force=1&reason=…` 逐次放行并记日志；`ARTEX_FINDING_GATE=off`
  是迁移旧数据的逃生口。设计见 [08-0day-pipeline.md](08-0day-pipeline.md)。

## 9. 已知未变的风险与缺口

1. **指纹未改**：`enrich/enrich.go:233` 仍发 `User-Agent: artex-enrich/1.0`。这是个可识别特征，
   对隐蔽性不利；改指纹属于逃避检测范畴，需要使用者自行决定（默认保留便于溯源与审计）。
2. **规范原文未随仓库发布**：需要使用者自行取得并放到 `policy/spec/`（否则握手令牌校验缺来源）。
3. **0day 流水线阶段 2–4 未固化**：候选生成、可达性、触发验证仍靠 agent 自主发挥。
4. **准入凭据未与流量交叉校验**：反例 `evidence` 目前是自由文本，下一步要求引用真实 traffic id。
